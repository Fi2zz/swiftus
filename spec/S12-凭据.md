# S12 · 凭据

版本：v1.1（**全量来源**：契约 + env / memory / file / vault / aws；SigV4 签名链见 S15） · 日期：2026-09-28 · 来源：conatus_credentials
语言中立规格。Swiftus 实现注记见文末。

## 1. Credential 值对象

- 字段：`key`（如 `ARK_API_KEY`）、`value`（明文，**绝不入日志**）、`expiresAt?`（空 = 永不过期）。
- `masked`：脱敏表示，规则见 S3 §2（maskSecret）。
- `expired`：仅当 `expiresAt` 非空且早于当前时刻（过期即视为没有）。
- `toString` 只含键名与 masked，不含明文。

## 2. 错误码（CredentialsException：code / message）

- `missing`：缺少凭据（require / validate）；`read-only`：只读来源被写。
- 远端来源（v1.1 增补）：`vault-http`（Vault 返回非 200，消息含状态码）/ `vault-network`（网络层异常，消息含原因）；`aws-http`（Secrets Manager 返回非 200）/ `aws-network`（网络层异常）；
- `invalid-source`（v1.1，Swift 侧新增码）：文件来源的内容不是合法 JSON（Dart 侧此处抛无机器码的 `FormatException`，见实现注记的偏离记录）。

## 3. 来源枚举

`env` / `file` / `memory` / `vault` / `aws`（v1.0 只实现 env 与 memory；v1.1 补齐 file / vault / aws）。**内置来源仅此五种**；另有 Swift 侧的「可插拔来源」扩展点（见 §7.5），供宿主自有存储（如 Keychain）接入，**不计入本枚举**。

## 4. parseCredentialMap（四来源共用的 JSON 解析口径）

输入为动态 JSON 对象，每项两种形态：

- 字符串 —— 直接作为值；
- 对象 —— 读 `value`（字符串，缺则跳过该项）与可选 `expiresAt`（ISO 8601 字符串，解析失败视为无）。

输入不是对象时返回空表；键非字符串、值形态不合法（数字、布尔等）的项一律跳过。

## 5. CredentialSnapshot（内存快照 + 变更广播）

- `get(key)`：不存在或**已过期**返回空。
- `update(credential)`：写入并推送变更；已关闭时忽略。
- `refreshSnapshot(values)`：整体替换快照，并逐一推送**新增或发生变化**的凭据（value 或 expiresAt 不同即变化）；**移除无法表达，不推送**。
- `close()`：幂等；关闭后写入被忽略。
- `keys`：快照中键的不可变副本。

## 6. Credentials 契约

- 读取**同步**（读内存快照）：`get`（找不到或已过期返回空）、`require`（空则抛 `missing`：`缺少凭据 "k"。`）、`validate(keys)`（任一缺失即快速失败，消息列出**全部**缺失键：`缺少凭据：a, b`）。
- `update(key, value)`：**只读来源抛 `read-only`**；可写来源（memory）立即生效并推送。
- `changes`：更新或刷新后的变更广播（消费方按键订阅）。
- `refresh()`：从底层来源重拉快照；默认无操作。
- `close()`：释放来源（取消订阅与定时器）；幂等。

## 7. 来源语义

### 7.1 进程内来源

- **EnvCredentials**（只读）：构造时把全部**非空**环境变量装入快照；`refresh` 重读环境映射（测试可注入自定义映射）；`update` 抛 `read-only`（`环境变量凭据是只读来源。`）。
- **InMemoryCredentials**（可写）：`initial` 建初始快照；`update` 立即生效并推送；适合进程内临时凭据与测试替身。

### 7.2 文件来源（v1.1 增补）

- **FileCredentials**（只读）：读 `path` 处的 JSON 文件，**两种形态都支持**——`{"K": "v"}` 与 `{"K": {"value": "v", "expiresAt": "…"}}`（解析口径同 §4）；
- 构造后需显式 `load()`（或 `refresh()`，二者等价）把文件读进快照；**文件不存在时**用构造参数 `fallback`（键值对表）兜底，都没有则快照为空；
- 文件内容**不是合法 JSON 时 `load` 抛错**（`invalid-source`）；顶层是合法 JSON 但不是对象时按空表处理（不抛错，见 §4）；
- `update` 抛 `read-only`（`文件凭据是只读来源。`）；
- `refreshInterval` 非空时 `load` 之后自动起定时刷新，每次到点重读文件（见 §9），`close` 取消。

### 7.3 Vault 来源（v1.1 增补）

- **VaultCredentials**（只读）：`GET {address}/v1/{mount}/data/{path}`，头带 `X-Vault-Token: {token}`；`address` 末尾斜杠可有可无（规范化后拼接），`mount` 缺省 `secret`；
- 解析：响应 JSON 的 `data.data` 交给 §4 的 `parseCredentialMap`（每项可是字符串或 `{value, expiresAt}` 对象）；顶层不是对象 / 无 `data` / `data.data` 不是对象 / 内容非法 → **空表**（不抛错）；
- `update` 抛 `read-only`（`Vault 凭据是只读来源。`）；非 200 → `vault-http`（`Vault 返回 HTTP <code>。`）；网络异常 → `vault-network`（`访问 Vault 失败：<原因>`）；
- `refreshInterval` 非空时首次 `refresh` 之后起定时刷新，`close` 取消。

### 7.4 AWS Secrets Manager 来源（v1.1 增补）

- **AwsSecretsCredentials**（只读）：`POST` 到 `https://secretsmanager.{region}.amazonaws.com/`（或 `config.endpoint` 覆盖，供 VPC Endpoint / localstack / 测试替身），请求体 `{"SecretId": "…"}`，业务头 `Content-Type: application/x-amz-json-1.1` + `X-Amz-Target: secretsmanager.GetSecretValue`；**全部请求头经 S15 的 SigV4 签名**（service 固定 `secretsmanager`）；
- 解析：响应 JSON 的 `SecretString` 先按 JSON 对象展开（§4 口径，非法 JSON 视为空表）；**展开结果为空时**以 `secretId` 为单一键、整个 `SecretString` 为值（兼容纯文本 secret）；顶层不是对象或 `SecretString` 不是字符串 → 空表；
- `update` 抛 `read-only`（`AWS 凭据是只读来源。`）；非 200 → `aws-http`（`Secrets Manager 返回 HTTP <code>。`）；网络异常 → `aws-network`（`访问 Secrets Manager 失败：<原因>`）；
- `refreshInterval` 非空时首次 `refresh` 之后起定时刷新，`close` 取消。

### 7.5 可插拔来源（Swift 侧扩展，非 conatus 移植项）

conatus 无对应抽象；这是 Swiftus 为「宿主自有凭据存储」（如 macOS / iOS Keychain）留的扩展点，把 S12 的完整语义套在一个最小端口上，调用方只需实现存取本身。**它不是第六种内置来源**——`CredentialsSource` 枚举不为其加 case。

- **`CredentialStore`（端口，只读）**：`func load() async throws -> [String: Credential]`，返回键→凭据表（键与 `Credential.key` 一致）。抛出的错误原样透传给调用方。
- **`WritableCredentialStore: CredentialStore`**：追加 `func set(_ credential: Credential) async throws`。只读存储**无需**实现此协议。
- **`StoreCredentials: Credentials`（适配器）**：把端口套上完整的 S12 语义——
  - 快照 / 变更推送 / `keys` 由内部 `CredentialSnapshot`（§5）承担；`get` 同步读快照（首次须显式 `refresh()` 才入快照，与 §7.2 一致）；
  - `refresh()`：调 `store.load()` 后整体替换快照（推送口径同 §5）；首次拉取成功后，`refreshInterval` 非空则起周期任务（至多一个、`close` 取消，纪律同 §8）；
  - `update(key, value)`：store 是 `WritableCredentialStore` 时**先 `set` 成功、再写快照**（介质领先内存；写失败时快照不变且错误原样抛出）；否则抛 `read-only`（`该凭据来源是只读来源。`）；
  - `close()`：取消周期任务并关闭快照；幂等。

## 8. 刷新调度纪律

- 三种来源的 `refreshInterval` 语义一致：**空 = 只在显式 `refresh()` / `load()` 时拉取**；非空 = 首次拉取成功后起周期任务，每次到点重拉；
- 周期任务**至多一个**（重复 `load` / `refresh` 不叠加）；`close` 取消周期任务并关闭快照（幂等）；
- 周期任务里的拉取失败**不打断后续调度**（错误按 §2 的码抛出给显式调用方，周期路径静默继续）；
- 时间源只接受注入缝（见实现注记），测试以受控等待器推进，不依赖真实墙钟。

## 9. 装配（provideCredentials）

- 以 `'credentials'` 服务键提供到上下文；缺省为 EnvCredentials；`close()` 随上下文释放登记；同上下文重复提供抛错（沿 S2 provide 语义）。

## Swiftus 实现注记（偏离记录）

- **changes 通道形态**：Dart 为 broadcast `Stream`（异步推送）；Swiftus 在同一串行域（`@ContextTreeActor`）内改为**同步监听列表**（add/removeChangeListener，令牌注销）。消费方与来源同域，无跨线程时序差异；与 Reactor 的广播模型一致。
- **过期判定的时钟**：`expired(now:)` 与快照 `get(_:now:)` 接受注入时刻（默认系统钟），保证测试确定性；待 Clock 统一纪律落地（方案书 §5.5）时回接。
- **ISO 8601 解析**：以 ISO8601DateFormatter 承载，与 Dart `DateTime.tryParse` 的兼容面略有差异（如仅日期无时间的串），暂记；
- **`refresh` 可抛错**：Dart 的 `Credentials.refresh` 会抛来源错误（`vault-http` 等），故本规格把端口的 `refresh` 定为可抛错（v1.0 的非抛错签名为最小集遗留）；env / memory 仍是不抛错的实现；
- **文件内容非法 JSON 的错误形态**：Dart 抛 `FormatException`（无机器码），Swift 收敛为 `CredentialsException(.invalidSource)` 以便调用方按码路由（Dart 行为 / Swift 修正语义 / 理由：机器码是本规格的路由约定，FormatException 无法按码处理）；
- **远端来源的传输**：Dart 用 `package:http` 并允许注入 `http.Client`；Swiftus 统一 URLSession（AGENTS 已定网络层），来源接受注入的 `URLSession`（测试用 `URLProtocol` 桩），因此「网络异常」在 Swift 侧的判定面是 URLSession 的错误（含非 HTTP 状态码），其余语义（请求形状、解析、错误码、只读、周期刷新）逐一与本规格对齐；
- **周期刷新的时间缝**：三来源的周期任务经 `RefreshClock` 缝驱动（生产 `Task.sleep`，测试注入受控等待器），落实 AGENTS「时间模块只接受注入的 Clock」纪律；周期任务本体是脱离调用栈的 `Task`，错误静默吞掉（周期路径不打断后续调度）。
- **可插拔来源（§7.5）是 Swift 侧扩展**：`CredentialStore` / `WritableCredentialStore` / `StoreCredentials` 无 conatus 对应物（Dart 侧只有「让调用方自己 `implements Credentials`」一条路），故不进 fixtures，只由 Swift 侧单元测试守语义；不改动 §7.1–§7.4 任何内置来源。端口的阻塞面（Keychain 等系统调用）由调用方放到专用队列，避免占用协作线程池（AGENTS 坑 #10）。
