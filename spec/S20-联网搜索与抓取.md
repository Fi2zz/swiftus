# S20 · 联网搜索与网页抓取

版本：v1.0 · 日期：2026-09-29 · 来源：conatus_search（12 个源文件：`search_types` / `search` / `search_registry` / `search_http` / `search_markup` / `search_tavily` / `search_exa` / `search_brave` / `search_duckduckgo` / `web_tools` / `fetch/fetcher` / `fetch/http_fetcher` / `fetch/firecrawl_fetcher`）

语言中立规格。Swiftus 实现注记见文末。
前置：S5（工具管线）、S12（凭据：Key 的唯一来源）。

范围说明：把「多 provider 顺序回退的搜索能力缝」与「URL → 模型可读正文」的抓取缝忠实搬过来。**调度与执行不归本规格**：这里只负责查、解析、清洗、投影、暴露工具。

## 1. 词汇与常量

- 搜索结果 `SearchResult`：`title` / `url` / `snippet`（缺省空串），序列化为 `{title, url, snippet}` 三个键的 JSON 对象；
- provider 契约 `SearchProvider`：`name`（诊断与显式路由用）+ `search(query, limit = 5)`；**只负责一次查询**，失败抛 `SearchException`，回退由 `SearchService` 编排；
- `SearchException(message)`：人可读失败说明，无错误码（消息即契约，工具结果直接透出）；
- 抓取接缝 `WebFetcher`：`fetch(url, maxChars = 20000) -> FetchedPage`，失败抛 `FetchException`；
- `FetchedPage`：`url`（原样回显传入值）/ `content`（已按 `maxChars` 截断）/ `format`；
- `FetchedFormat`：`text`（剥离标签后的纯文本）/ `markdown`（已转换的 markdown）；
- 凭据键名：`TAVILY_API_KEY` / `EXA_API_KEY` / `BRAVE_API_KEY`（搜索）、`FIRECRAWL_API_KEY`（抓取）；
- 缺省搜索源顺序 `["tavily", "exa", "brave", "duckduckgo"]`；
- 上限：Tavily `max_results ≤ 20`、Brave `count ≤ 20`；抓取正文缺省 20000 字符；provider 查询超时缺省 **15 秒**，HTTP 抓取 30 秒，Firecrawl 60 秒。

## 2. SearchService（服务键 `search`）

- `register(provider)`：**追加**到 provider 列表并返回**幂等**撤销函数（撤销即从列表移除，可重复调用）；
- `providers` 按注册顺序；`get(name)` 未注册返回空；
- `search(query, limit = 5, provider?)`：
  - **不指定 `provider`**：按注册顺序逐个尝试，**第一个不抛异常的就返回它的结果**——**返回空列表算成功**（不继续回退）；
  - **指定 `provider`**：只走该 provider；未注册 → `SearchException("未注册的搜索 provider \"<name>\"")`；
  - 候选为空（无 provider）→ `SearchException("没有可用的搜索 provider")`；
  - 全部抛异常 → `SearchException("所有搜索 provider 都失败：<name>: <原因>；<name>: <原因>")`（**逐个源用全角分号 `；` 连接**，每项形如 `<provider>: <错误>`，其中 `<错误>` 是该异常 `toString()` 的可读部分）；
- `statuses`：**装配期**状态快照（哪些源可用、哪些被跳过及原因），**动态 `register` 不改变它**。

## 3. 装配 `provideSearch`

解析优先级（先命中先赢）：

1. 显式 `providers` → 按序注册这些实例，**忽略 `order`**，`statuses` 为**空**；
2. 传入现成的 `search` → **不追加任何 provider**，`statuses` 为空；
3. 否则按 `order` 构造：
   - `credentials` 缺省取上下文已提供的 `credentials` 服务；**两者都没有**时只装配免 Key 的 `duckduckgo`，其余源记「未提供凭据服务」；
   - 有凭据服务时按 §4 的规则逐个解析。

注册经上下文效应登记：上下文释放即撤销全部注册（provider 列表回到空）。

## 4. 源解析表

- 内置表覆盖四个源：`tavily` / `exa` / `brave` / `duckduckgo`；`duckduckgo` 的凭据键为空串（**免 Key，始终可用**）；
- 按 `order` 逐个解析，产出一个**可用 provider 列表**（按 order 顺序）与一个**与 order 同序的状态列表**（含被跳过的源）：
  - 名字未在表内 → 跳过，状态 `available: false`、原因「未知的搜索源」；
  - 需要 Key 但 `credentials.get(key)` 为空 → 跳过，状态 `available: false`、原因「缺少 <KEY>」（含键名）；
  - 其余 → 构造 provider，状态 `available: true`、原因空串；
- `order` 决定顺序，**未列出的源不参与**（连状态都不出现）。

## 5. provider 协议细节

各 provider 只在「非 200」「非对象 JSON」「超时」三种情况下抛 `SearchException`；解析阶段的缺字段一律降级为空串。

- **tavily**：`POST <endpoint>`，头 `content-type: application/json`、`authorization: Bearer <key>`，体 `{"query": q, "max_results": <limit clamp 1..20>, "search_depth": "basic"}`；响应取 `results[]` 的 `title` / `url` / `content`（**不做标记清洗**）；非 200 → `tavily HTTP <code>`；非对象 → 「tavily 返回了非对象 JSON」；缺 `web` 之类的容器不存在时返回**空列表**；
- **exa**：`POST <endpoint>`，头 `content-type: application/json`、`x-api-key: <key>`，体 `{"query": q, "numResults": <limit>, "contents": {"text": {"maxCharacters": 500}}}`；响应取 `results[]` 的 `title` / `url` / `text`，`text` 缺失时回落 `summary`；非 200 → `exa HTTP <code>`；非对象 → 「exa 返回了非对象 JSON」；
- **brave**：`GET <endpoint>?q=<query>&count=<limit clamp 1..20>`，头 `accept: application/json`、`x-subscription-token: <key>`；响应取 `web.results[]` 的 `title` / `url` / `description`（**经标记清洗**，见 §6）；`web` 缺失 → 返回**空列表**；非 200 → `brave HTTP <code>`；非对象 → 「brave 返回了非对象 JSON」；
- **duckduckgo**：`GET <endpoint>?q=<query>`，头 `user-agent: <常见浏览器 UA>`；响应按 §7 解析 HTML；非 200 → `duckduckgo HTTP <code>`；
- **超时**：任一 provider 的请求超过 `timeout` → `SearchException("<provider> 请求超时（<秒>s）")`（秒数为整数）。

## 6. 标记清洗

- `stripMarkup(html)`：去掉所有标签 → 解常见实体（`&amp;` `&lt;` `&gt;` `&quot;` `&#39;` `&nbsp;`）→ `trim`。用于 DuckDuckGo 的标题/摘要与 Brave 的 `description`——**snippet 会原样进入模型可见输出，故在 provider 边界统一清洗**；
- `stripHtml(html)`：先整块去掉 `<script …>…</script>` 与 `<style …>…</style>`（替换成单空格）→ **标签替换成空格**（不是删空）→ 解常见实体 → 把 `[ \t\r\n]+` 压缩成单空格 → `trim`。用于 HTTP 抓取的正文。

## 7. DuckDuckGo HTML 解析

- 标题锚点：`<a …class="result__a"…>…</a>`（大小写不敏感、跨行匹配）；摘要锚点：`<a …class="result__snippet"…>…</a>`；链接取同一 `<a>` 上的 `href="…"`；
- **链接解码**：`//` 开头的补 `https:`；随后取查询参数 `uddg` 的值作为真实链接，**没有 `uddg` 就用补全后的原值**；
- **按序配对**：第 i 个标题锚点配第 i 个摘要锚点（摘要越界则为空串）；
- 标题或链接任一为空 → **跳过该条**（不占 limit 名额）；
- 结果数达到 `limit` 即停；无任何匹配 → 返回**空列表**（不抛错）；
- 标题与摘要都经 §6 的 `stripMarkup`。

## 8. 抓取

- **`HttpFetcher`（默认后端）**：校验链接（必须是 `http` / `https` **且带主机名**，否则 `FetchException("仅支持带主机名的 http/https 链接：\"<url>\"")`）→ `GET` → 非 200 → `FetchException("HTTP <code>")`；正文经 §6 的 `stripHtml` 后按 `maxChars` **截断**（超长直接切前 `maxChars` 个字符，不加省略号），`format` 为 `text`；
- **`FirecrawlFetcher`**：同一套链接校验与失败语义，`POST <endpoint>`、头 `content-type: application/json`、`authorization: Bearer <key>`、体 `{"url": <url>, "formats": ["markdown"]}`；
  - 非 200 → `Firecrawl HTTP <code>`；
  - 响应不是 JSON → 「Firecrawl 返回了非 JSON 响应」；不是对象 → 「Firecrawl 返回了非对象 JSON」；
  - `success` 显式为 `false` → `Firecrawl 抓取失败：<error 字段>`（缺 `error` 用「未知原因」）；
  - 缺 `data` 或不是对象 → 「Firecrawl 响应缺少 data」；
  - `data.markdown` 缺失 → **正文为空串**（不算失败）；存在但不是字符串 → 「Firecrawl 返回了非字符串的 markdown」；
  - `format` 为 `markdown`；
- 超时 → `FetchException("请求超时（<秒>s）")`（HTTP 后端）/ `Firecrawl 请求超时（<秒>s）`；
- 传输层失败（DNS / 连接 / TLS）→ `FetchException("抓取失败：<原因>")`；**调用方只需捕获 `FetchException` 一种**。

## 9. 工具（两个，均经 S5 管线注册，均为 low 风险）

| 工具 | 参数 | 成功文本 | 成功结构化值 | 失败 |
|---|---|---|---|---|
| `web_search` | `query`（必填）/ `limit` | 见下 | `SearchResult` 的 JSON 数组 | 文本 + 码 `SEARCH_UNAVAILABLE` |
| `fetch_url` | `url`（必填） | 正文原文 | `{url, format}`（`format` 取形态名） | 文本 + 码 `INVALID_URL` / `FETCH_FAILED` |

- `web_search` 文本：首行 `搜索 "<query>" 的结果：`，随后每条 `"\n<N>. <title>"` + `"\n   <url>"`，**摘要非空时**再加 `"\n   <snippet>"`（N 从 1 起）；
- `web_search` 空结果：成功，文本 `未找到与 "<query>" 相关的结果`，结构化值为**空数组**；
- `web_search` 失败文本：`无法联网：所有搜索源都不可用。\n<SearchException 消息>`；**若 `statuses` 里有不可用的源**，再追加 `"\n未配置的搜索源：<name>（<reason>）"`（多个用全角 `；` 连接；没有则不追加这一行）；
- `fetch_url` 链接**协议**不是 http(s)（含无法解析的串）→ 文本 `仅支持 http/https 链接："<原始输入>"`、码 `INVALID_URL`；注意「有 http 协议但缺主机名」在这一层是**放行**的（协议合法），随后由抓取后端按 §8 的链接校验失败 → 落到 `FETCH_FAILED`；
- `fetch_url` 抓取失败 → 文本 `无法联网：抓取 <url> 失败。<FetchException 消息>`、码 `FETCH_FAILED`；
- `limit` 缺省取工具构造时的 `defaultLimit`（缺省 5）。

## 10. 装配 `provideWebTools`

- `search` 缺省取上下文的 `search` 服务；
- `fetcher` 优先级：**显式传入** > 上下文（或显式）的 `credentials` 里有 `FIRECRAWL_API_KEY` 时用 `FirecrawlFetcher` > `HttpFetcher`；
- 两个工具的注册经上下文效应登记。

## 11. 有意偏离

- **HTTP 客户端**：`package:http` 的 `http.Client` 注入点改为 **URLSession + `URLProtocol` 桩**（仓内既有做法，见 S12 / S15）。请求的构造语义（方法、头、查询项、体）逐字对齐，差异只在「查询串编码的具体转义」——fixtures 因此投影**解码后的查询项**而非原始 URL 串；
- **超时实现**：`Future.timeout` 改为 URLSession 的 `timeoutInterval`（抓取）与显式竞速（provider），超时消息逐字一致；
- **传输层失败分类**：Dart 侧 `http.ClientException` 与 `dart:io` 的 `IOException` 分两类文案，本移植把 URLSession 的所有传输错误归一为 `FetchException("抓取失败：<原因>")` 一种（调用方本来只捕获这一种）；
- **正则选项**：DuckDuckGo 解析用的两个正则在 Dart 侧是 `dotAll: true, caseSensitive: false`，Swift Regex 需要显式 `dotMatchesNewlines` + `.caseInsensitive`，否则跨行的 `<a>` 匹配不上；
- **系统抓取后端不做**：只搬 `HttpFetcher` 与 `FirecrawlFetcher` 两个后端（与来源同），不引入 headless 浏览器。

## Swiftus 实现注记

- `SearchService` / 各 provider / `WebFetcher` 实现全部 `@ContextTreeActor`；`SearchProvider` / `WebFetcher` 协议显式标 `: Sendable`；
- **provider 与 fetcher 都接受注入的 `URLSession`**（测试用 `URLProtocol` 桩按 authority 分桶——用例并发时全局单 handler 会串台，S12 先例），端点、Key、timeout 全是构造参数，便于逐条 fixture 驱动；
- **时间不参与**：本规格没有时间语义（无墙钟、无时区），故 fixtures 不受 TZ 影响——与 S9 不同，导出器不需要钉时区；
- **HTML/标记清洗是纯函数**，直接导出成 fixtures（`search-markup`）——这是最容易被「随手重写」漂移的部分；
- **错误只有消息没有码**（`SearchException` / `FetchException`），与来源一致；工具层才把消息映射成 `SEARCH_UNAVAILABLE` / `INVALID_URL` / `FETCH_FAILED` 三个宿主可见码；
- fixtures **投影解码后的查询项**：Dart 的 `Uri.queryParameters` 与 Swift 的 `URLComponents.queryItems` 在 `+` 与 `%20` 的处理上不完全一致，逐字比 URL 串会把用例绑死在编码细节上；「方法 / 主机 / 路径 / 头名（小写）/ 解码后的查询项 / 请求体」这些语义面才进 fixture；
- 伞包 `import Swiftus` 会重导出本模块的 `SearchResult` / `SearchProvider` 等类型，命名与 `_Concurrency` / Foundation 无冲突。
