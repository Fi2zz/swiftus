# S17 · 任务中心（Task Center）

版本：v1.1（shell 追踪端口收口为 S18 的 `ShellExecutor`，§5.4 / §7 同步）· 日期：2026-09-28 · 来源：conatus_tasks（`task.dart` / `task_center.dart` / `task_center_default.dart` / `task_center_provider.dart` / `task_tools.dart` / `task_tracking.dart` / `agent_loop.dart` 的 `AgentTurnTracker`）
语言中立规格。Swiftus 实现注记见文末。
前置：S2（服务装配）、S3/S4（会话事件与派生状态）、S5（工具管线）、S6（Prompt 装配）、S8（调度交付缝）、S16（Agent Loop 与 spawn_agent / approval / telemetry / goal / planMode）。
范围说明：任务中心只回答「现在有哪些任务在跑、各自什么状态、能不能取消」，**不调度也不执行**；任务由运行时组件（Agent Loop 轮次 / sub-agent / shell / schedule）创建。shell 执行器本身属 Foundation 能力域（**S18**），本域只给追踪装饰器（见 §5.4 与 §7）。

## 1. 词汇与事件协议

- 事件类型 `task/changed`：任务状态整值替换持久化到会话（append-only，按任务 id 折叠最后一条）；派生只折叠会话**自身后缀**（fork 出的会话不继承父会话的任务树）；
- 恢复时未完成任务的统一失败原因常量 `kTaskStaleReason` = `进程重启，执行环境已丢失`；
- `TaskStatus`：`pending`（已创建待执行）/ `running`（执行中）/ `paused`（暂停）/ `completed` / `failed` / `cancelled`（后三者为终态）；
- `TaskKind`：`agentTurn`（Agent Loop 一轮）/ `subAgent`（子 Agent 委托）/ `shell`（后台 shell 进程）/ `schedule`（定时提醒交付）/ `custom`（自定义）；
- `Task`：`{id, kind, status, description, createdAt, startedAt?, finishedAt?, parentTaskId?, metadata, result?, error?}`。`parentTaskId` 表达任务树（Goal → Agent Turn → Sub-Agent → Shell）；`metadata` 可放 `goalId` / `maxRounds` / `command` 等；
- 状态谓词：`isTerminal` = completed / failed / cancelled；`isActive` = pending / running / paused（两个集合互为补集）；
- `duration`：`startedAt` 为空时为 nil，否则 `(finishedAt ?? now) - startedAt`；
- 不可变更新 `copyWith`：`status` / `startedAt` / `finishedAt` 传空表示**保持原值**；`result` / `error` 传空同样保持原值，但可显式置为 JSON null 以清除（原对象不受影响）；
- JSON 往返：序列化为 `{id, kind.name, status.name, description, createdAt, startedAt, finishedAt, parentTaskId, metadata, result, error}`，可空字段保留 null 键；`result` / `error` 尽量保留 JSON 结构，不可编码的值退化为字符串；
- 宽容反序列化：`kind` 未知回落 `custom`、`status` 未知回落 `pending`、`startedAt` / `finishedAt` 解析失败按 nil、`metadata` 缺失按空表（载荷必须为对象）；**`createdAt` 缺失或非法直接抛错**（唯一不宽容字段）；
- `restoreTaskState(session)`：折叠会话自身后缀的 `task/changed` 事件，按任务 id 还原任务表（每个 id 只保留最后一个事件）；
- `TaskException`：`{code, message}`，稳定机器码全集 `not-found` / `already-terminal` / `cancelled`（审批拒绝）/ `disposed`（中心已释放）；展示形如 `TaskException(<code>): <message>`。

## 2. TaskCenter 端口（服务键 `tasks`）

- `create(kind, description, parentTaskId?, metadata?)`：创建任务，落 `pending` 状态，返回新任务；
- `update(id, status?, result?, error?)`：更新任务状态——
  - 任务不存在抛 `not-found`；任务已是终态抛 `already-terminal`；
  - `status` 进入 `running` 且原 `startedAt` 为空时自动填入当前时刻；
  - `status` 发生变化且变化后为终态时自动填入 `finishedAt`；
  - `result` / `error` 传空表示不改；
  - 计算后与原值**完全相同**时不落盘、不埋点、不广播（直接返回原任务）；
- `get(id)`：单个任务，不存在返回 nil；`all`：全部任务（不可变视图）；`active`：活跃任务（pending + running + paused）；
- `childrenOf(parentId)`：直接子任务（`parentTaskId` 相等，按入表顺序）；`subtreeOf(id)`：以 id 起点的**栈式深度优先**遍历（先自己，再展开其子；子任务按入表顺序的**逆序**入栈），不存在的 id 静默跳过、不出现在结果里；
- `cancel(id)`：取消任务——① 任务不存在抛 `not-found`，已终态抛 `already-terminal`；② **shell 类任务且提供 approval 时**先走审批（请求 `id = cancel-<taskId>`、`toolName = cancel_task`、参数 `{id, description}`、说明 `取消任务「<description>」？`），拒绝抛 `cancelled` 且**不改动任何状态**；③ 级联取消所有**活跃**子任务（深度优先，先子后己）；④ 取出并执行 `registerCancel` 注册的取消回调（允许覆盖注册）；⑤ 落 `cancelled` + `finishedAt`、持久化、埋点、广播；
- `cancelChildren(id)`：取消 id 的所有活跃子任务，不取消自己；
- `registerCancel(id, canceller)`：注册 / 覆盖取消回调；
- `changes`：任务变更流，每次状态落盘后广播最新整值；
- `restore(session)`：从会话恢复状态（见 §3.5）；
- `dispose()`：释放资源，幂等；释放后 `create` / `update` / `cancel` 抛 `disposed`。

## 3. DefaultTaskCenter

### 3.1 能力缝

四个可选依赖，**显式传入优先，缺省从上下文惰性解析，仍缺省则降级**：`session`（持久化 `task/changed` 事件）、`approval`（shell 类任务取消确认，缺省不拦）、`telemetry`（埋点）、`tools`（仅装配时用，缺省取 `ctx.tools`）。提供 session（显式或上下文可解析）时**构造即自动 restore**。

### 3.2 create

序号自增；任务 id 形如 `task-<序号>-<创建时刻微秒>`；落 `pending`、入表、持久化、埋点 `task.created`、广播。

### 3.3 埋点事件

`telemetry.emit` 的事件名与载荷 `{id, kind, status, description}`：

| 时机 | 事件名 |
|---|---|
| create | `task.created` |
| 状态迁移 pending → running | `task.started` |
| paused → running | `task.resumed` |
| running → paused | `task.paused` |
| 任意非终态 → completed | `task.completed` |
| 任意非终态 → failed | `task.failed` |
| cancel 落定 | `task.cancelled` |
| restore 判定为陈旧 | `task.failed` |

未列出的迁移（如 pending → pending、running → running、running → completed 之外的自环）**不埋点**。

### 3.4 update 与 cancel 的落盘口径

两者都先算新整值再落盘：入表 → 追加 `task/changed` 事件 → 埋点 → 广播。`update` 的埋点走 §3.3 迁移表；`cancel` 直接发 `task.cancelled`。`update` 无实际变化时不产生事件。

### 3.5 restore

绑定 session → 清空任务表 → 用 `restoreTaskState` 重填 → 逐个检查：非活跃（终态）任务原样保留；**活跃任务改判为 `failed`**，写入 `error = kTaskStaleReason` 与 `finishedAt`，并为该改判**再次持久化 + 埋点 `task.failed` + 广播**。

## 4. 模型侧工具

`create` 不暴露给模型——任务由运行时组件自动创建。返回文本面向语音场景口语化。

- 工具名 `list_tasks`（风险 low，说明 `列出当前任务。可按状态、类型、父任务过滤。`）：参数 `status`（枚举 pending/running/paused/completed/failed/cancelled）、`kind`（枚举 agentTurn/subAgent/shell/schedule/custom）、`parent_id`（字符串）；三者独立叠加过滤，均缺省列全部；
- 工具名 `cancel_task`（风险 medium，说明 `取消一个任务，会同时取消其所有子任务。`）：参数 `id` 必填；成功文案 `好的，已取消任务「<任务描述或 id>」。`；`TaskException` → 失败结果，content 为 `message`、error 为 `{code, message}`（**不抛到管线外**）；
- `describeTasks(tasks)` 播报文本（逐字协议）：
  - 空列表 → `现在没有任务。`；
  - 否则首行 `现在共 <N> 个任务：`，随后每任务一行 `\n<N>. <描述>（<状态文案>[，已运行 <时长>]` + `）`；
  - 状态文案：pending 等待中 / running 进行中 / paused 已暂停 / completed 已完成 / failed 已失败 / cancelled 已取消；
  - 时长文案：`duration` 非空才追加，整分钟数 ≥ 1 记 `<M> 分钟`，否则记 `<S> 秒`。

## 5. 运行时接入

依赖方向是「组件接入中心」而非「中心依赖组件`：装饰器由装配一次性挂好，Agent Loop / sub_agent / schedule / shell 的现有代码零改动。

### 5.1 轮次追踪端口（AgentTurnTracker）

- 端口：`beginTurn(userInput)` / `endTurn(result?, error?)`（result 为最终回复，error 为失败原因，二者互斥，可都为空）；
- Agent Loop 集成：`run(input)` 外壳——先 `beginTurn(input)`，再跑「单轮 + goalDriver 续行」，成功后 `endTurn(result: 回复)`；抛错时 `endTurn(error: err)` 后原样上抛；
- 未装配追踪器时行为与无追踪完全一致。

### 5.2 TaskTracking

- `beginTurn(userInput)`：建 `agentTurn` 任务，描述 `处理: <userInput>`，metadata 在有 goal 时写 `goalId`（当前目标 id）、plan mode 激活时写 `planMode: true`（两者都没有则 metadata 为空表），随后置 `running`，并记下本轮任务 id（`currentTurnTaskId`）；
- `endTurn(result, error)`：取出并清空本轮任务 id（无活跃轮次直接返回）；`error` 非空 → `failed` + `error`；否则 `completed` + `result`；
- `spawn_agent` 中间件：只拦 `spawn_agent`（其余调用原样放行）——建 `subAgent` 任务，描述 `子 Agent: <task 参数或空串>`，`parentTaskId` 取当前轮次任务 id，metadata 按参数存在性写 `tools` / `maxRounds`（键名 `max_rounds` → `maxRounds`），随即置 `running`；等工具结果后判结局——**结果失败，或结果值里 `status == failed`** → `failed` + `error`（结果值是对象时取其 `output`，否则取结果文本）；否则 `completed` + `result`（结果值原样）。子 Agent 的异常在结果值里收敛，故判定只能读结果值。

### 5.3 schedule 交付包装

包装提醒交付闭包：每次交付建一个 `schedule` 任务，描述 `提醒: <文本>`，置 `running`，按交付返回值落 `completed`（true）/ `failed`（false），并把布尔结果原样返回给调度器。

### 5.4 shell 执行包装

- 被追踪的执行端口即 **S18 的 `ShellExecutor`**（v1.0 时为本刀在任务域内定义的追踪用替身端口，v1.1 随 S18 收口为该端口本身）：`resolve` 补齐封顶、`run(spec)` 前台执行、`start(spec)` 后台句柄（`status` / `exitCode` / `done` / `readOutput()` / `kill()`）；
- 装饰器：每次执行建一个 `shell` 任务，描述 `Shell: <命令>`，metadata `{command: <命令>}`，随即置 `running`；
  - 前台：执行结束按 `exitCode == 0` 落 `completed` / 否则 `failed`，`result` 为 `{exitCode}`；
  - 后台：不阻塞返回，进程结束后按同一口径落定；追踪失败（中心已释放或任务已终态）时**静默让位**给执行结果本身，不外抛。

## 6. 装配

- `provideTaskCenter(ctx, {taskCenter?, session?, approval?, telemetry?, tools?, registerTools = true})`：解析或新建中心 → 提供 `tasks` 服务 → `registerTools` 为真时经上下文效应注册 `list_tasks` / `cancel_task` 两个工具 → 随上下文释放 dispose；
- `provideTaskTracking(ctx, {tasks?, registry?})`：`tasks` 缺省取 `ctx.tasks`、`registry` 缺省取 `ctx.tools`；经上下文效应挂 `spawn_agent` 中间件；再经依赖注入等待 `agentLoop`——就绪即把追踪器挂到轮次追踪端口，依赖消失或子上下文释放时若仍是同一个追踪器则摘除。

## 7. 有意偏离

- **`result` / `error` 的清除表达**：Dart 用哨兵对象区分「不修改」与「置 null」，Swift 无此哨兵惯用法——`copyWith` / `update` 传空一律表示保持原值，需要清除时显式传 JSON null。
- **`createdAt` 解码失败的错误形态**：Dart 由 `DateTime.parse` 抛 `FormatException`（无稳定机器码），Swift 抛 `TaskError.invalidCreatedAt`（唯一新增码，供 `restore` 路径收敛）；其余错误码与 Dart 一一对应。
- **shell 追踪端口归属（v1.1 已收口）**：v1.0 时 shell 能力域属 W3 未移植，任务域内自带追踪用替身端口（命令 / 退出码 / 进程句柄三要素）并登记为有意偏离；**S18 落地后该偏离作废**——装饰器改为包裹 S18 的 `ShellExecutor`，任务域内的替身端口删除，语义（建任务、按退出码落定、追踪失败静默）不变。退出码的**符号**随运行时而异（Dart `-9` / Foundation 信号号），按 S18 §4 只判「是否 0」。
- **任务标识与时刻**：Dart 任务 id 内嵌墙钟微秒；Swiftus 保持 `task-<序号>-<微秒>` 形状（序号与微秒都由注入的墙钟取样），但 fixtures 不含具体 id 与时刻（见 `tool/export_fixtures/README.md` 归一化规则）。
- **值类型改名 `SwiftusTask`（2026-10-10）**：Dart 侧名为 `Task`；Swift 的 `_Concurrency.Task` 无处不在，同名值类型会被伞包 `@_exported import` 重导出后遮蔽并发 `Task`（消费方裸 `Task { }` 编译失败，报「trailing closure passed to parameter of type 'JSONValue'」），且本 target 内所有闭包任务被迫写全 `_Concurrency.Task`。按规则 3（API 形状允许偏离、语义不偏离）改名 `SwiftusTask`；JSON 载荷、事件协议、工具文案均不含类型名，fixtures 零影响。回归由 `SwiftusUmbrellaTests` 守「裸 `Task` 不再被遮蔽」。

## Swiftus 实现注记

- `TaskCenter` 为 `@ContextTreeActor` 协议（服务键 `tasks`）；`DefaultTaskCenter` 为 `@ContextTreeActor final class`，状态直存在 actor 内，不另加锁盒；
- `SwiftusTask` / `TaskStatus` / `TaskKind` 为 Sendable 值类型（值类型本名 `Task`，为避开 `_Concurrency.Task` 遮蔽改名，见 §7），`TaskStatus` / `TaskKind` 用 `String` 原始值与 Dart 枚举名对齐；JSON 投影为 `var jsonValue: JSONValue` + `init(jsonValue:)`；
- `result` / `error` 统一为 `JSONValue?`（Dart 的任意对象退化为字符串的规则由 `taskErrorValue(_:)` 承担，`any Error` 传入时取其描述串）；
- `restoreTaskState` 返回 `[SwiftusTask]`（按 id 首次出现序）而非字典：Swift `Dictionary` 无序，而 Dart 的 `LinkedHashMap` 插入序会影响 `all` / `childrenOf` / `subtreeOf` 的遍历序（fixtures 比对遍历序）；
- `DefaultTaskCenter` 暴露 `clock` 取样缝（任务 id 的微秒与各时间戳都取自它），测试注入定值时钟保证 `duration` 类断言确定；
- `changes` 为 `AsyncStream<SwiftusTask>`（每次访问生成新订阅，语义对齐 Dart 的 broadcast Stream：只收订阅之后的事件）；
- `AgentTurnTracker` 端口定义在 SwiftusAgent（`AgentLoop.turnTracker`），SwiftusTasks 的 `TaskTracking` 实现它——依赖方向与 conatus 一致（Tasks 依赖 Agent，Agent 不依赖 Tasks）；
- 审批 / 埋点 / 会话三缝复用 SwiftusAgent 的 `Approval` / `Telemetry` 与 SwiftusFoundation 的 `Session`，惰性解析走 `ctx.get(.approval)` / `ctx.get(.telemetry)`；会话只显式传入（Swift 侧 `Session` 非上下文服务，与 `DefaultPlanMode` 同款取舍）；
- `describeTasks` 与两个工具的文案为逐字协议文本，中文口语化措辞不本地化；
- **fixtures 归一化**（S17 专用，导出器与运行器同款）：任务 id 按首次出现顺序替换为 `<task-N>`（Dart id 内嵌墙钟微秒）；`createdAt` / `startedAt` / `finishedAt` 不入投影，改为 `hasStartedAt` / `hasFinishedAt` 布尔；`error` 只投影形态且只取**持久化后**的载荷（内存态错误值的形态随语言类型系统而异），内容断言由用例的显式布尔承担；被信号杀死的进程退出码随平台而异，只投影 `resultKeys`。
