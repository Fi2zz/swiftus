# S7 · 压缩切点

版本：v1.0 · 日期：2026-09-27 · 来源：conatus_compaction 全包（`compaction.dart` / `compaction_engine.dart` / `compaction_types.dart` / `compaction_tool_pairing.dart` / `compaction_invariant.dart`）
语言中立规格。Swiftus 实现注记见文末。
前置：S3（Session 事件格式；`Session` / `SessionEvent` / 消息事件常量）。

## 1. 词汇

- `CompactionId`：一次压缩交易的稳定身份，贯穿 start / summary / end 三个事件；形如 `cmp-<微秒级 Unix 时间戳>-<进程内单调序号>`。
- `CompactionSummary`：一次汇总的产出——`text`（摘要文本）+ 可选 `provider` / `model`（写摘要的提供方与模型，随摘要落进日志）。
- `Summarizer`：汇总器，由调用方注入（通常是 llm 能力）；接收待折叠的事件列表与上一版摘要文本，异步返回 `CompactionSummary`。
- `CompactionFold`：一次折叠的输入——`events`（待折叠事件，日志开头的一段）、`previous`（上一版滚动摘要，首次为空串）、`kept`（本次压缩后保留为原文的事件数）。
- `CompactionResult`：一次压缩的结局——`compactionId` / `startSeq` / `summarySeq` / `endSeq` / `summary` / `shadowedSeqs` / `kept`；`compacted` = 被折叠事件数（`shadowedSeqs` 长度）。

## 2. 服务契约（CompactionEngine，服务键 `compaction`）

| 成员 | 语义 |
|---|---|
| `keepRecent` | 保留为原始日志的最近事件数（实例预算）；构造时负数快速失败 |
| `summaryOf(sessionId)` | 该会话当前的滚动摘要；尚未压缩过为 nil |
| `forget(sessionId)` | 丢弃该会话的摘要记忆 |
| `compactIfNeeded(session, summarize, {keepRecent})` | 超预算时折叠并返回 `CompactionResult`；没有可折叠的平衡切点时返回 **nil**；`keepRecent` 覆盖实例预算（仅本次调用） |
| `provideCompaction(ctx, {engine})` | 装配到上下文，服务键 `compaction`；缺省构造默认实现 |

摘要记忆是**进程内表**（`compaction/summary` 是持久记录，滚动摘要本身不从日志重建）；fork 或重开进程后需要重新压缩（对齐 Dart 侧现有限制）。

## 3. 折叠规则（compactIfNeeded）

1. `keep` = 调用覆盖 ?? 实例 `keepRecent`；`total` = 会话当前事件数；
2. 预算切点 `cut = balancedCutAtOrBefore(session, total - keep)`（§5 吸附）；
3. `cut <= 0` → 返回 nil，日志不动（含 `keep >= total` 的情形：预算切点不为正，无事可折叠）；
4. 成功路径，**顺序追加**三个事件（载荷全集见 §4）：
   - append `compaction/start`；
   - 取 `folded = events[0..<cut]`，以 `(folded, previous)` 调用汇总器（`previous` 为该会话摘要记忆，首次为空串）；
   - append `compaction/summary`（`shadowedSeqs` = folded 各事件 seq，按日志顺序；`kept = total - cut`——吸附后实际保留条数，**不是** keepRecent 形参）；
   - append `compaction/end`（无 error）；
   - 摘要记忆更新为新版摘要文本；
5. 失败路径：汇总器抛错 → append `compaction/end`（`error` = 错误的展示串）→ 异常**原样上抛**；摘要记忆**不更新**；
6. 压缩不重写日志：被折叠的事件仍在日志里，三个 `compaction/*` 事件是**纯记录**——它们只记下一次压缩的边界与输入，不参与消息派生。

## 4. 日志协议（三事件载荷）

| 事件 | 载荷 |
|---|---|
| `compaction/start` | `compactionId`、`keepRecent`（本次生效的 keep） |
| `compaction/summary` | `compactionId`、`summary`、`shadowedSeqs`（int 数组）、`kept`（int）；`provider` / `model` 仅在汇总产出声明时落笔 |
| `compaction/end` | `compactionId`；失败时附 `error`（字符串） |

`CompactionResult.startSeq / summarySeq / endSeq` 即三个事件落定后的 seq（紧接压缩前日志末尾，依次递增）。

## 5. 工具配对平衡（切点安全）

压缩切点不能把助手的工具调用与它的 `tool/result` 劈到两边——保留窗口若以孤立的工具结果开头，模型会收到没有对应调用的 tool 消息。

### 5.1 平衡定义

- 每条事件对「未闭合工具调用数」的增量：`assistant/message` → `data.toolCalls` 为数组时 +其长度（data 非对象、或 toolCalls 缺失 / 非数组，计 0）；`tool/result` → −1；其余类型 → 0；
- N 条事件有 N + 1 个切点：切点 i（`0...N`）表示「折叠前 i 条事件」；**切点 0 恒平衡**；切点 i 平衡 ⟺ 前 i 条增量折叠后未闭合数为 0；
- 折叠过程中未闭合数一旦变负（`tool/result` 先于其调用出现，日志错位）→ 抛错（StateError 级），且**不留半推进的缓存状态**；
- 平衡状态按事件顺序**增量折叠并按会话缓存**，重复查询只折叠新增尾部，不重读全量。

### 5.2 查询与吸附

- `toolPairingBalancedBefore(session, seq)` / `toolPairingBalancedAfter(session, seq)`：该事件之前 / 之后的切点是否平衡；`seq` 不在日志里抛错（StateError 级）；日志错位同 §5.1 抛错；
- `balancedCutAtOrBefore(session, cut)`：从切点 `cut` **向前（含 cut）**找第一个平衡切点并返回；找不到（切点 1...cut 全不平衡）返回 0；`cut <= 0` 返回 0。

## 6. 日志不变式（checkCompactionInvariant）

纯函数：扫一遍事件列表，返回全部违规描述（空列表 = 通过）；`assertCompactionInvariant` 为开发模式断言版（违规非空抛错，消息为 `压缩日志不变式被破坏：\n<违规逐行连接>`）。

扫描状态机：进行中的压缩身份 `openId`（可空）+ 本次压缩是否已见 summary。

### 6.1 违规全集

| # | 触发 | 违规文案 |
|---|---|---|
| 1 | `compaction/start` 出现时已有未收尾压缩 | `seq N 的 compaction/start 之前，身份 X 的压缩还没有收尾` |
| 2 | `compaction/start` 缺 compactionId（data 非对象 / 缺键 / 非字符串 / 空串） | `seq N 的 compaction/start 缺少 compactionId` |
| 3 | `compaction/summary` 身份 ≠ openId（含一方缺失） | `seq N 的 compaction/summary 身份 Y 与进行中的压缩 X 不一致`（缺失侧显示 `（缺失）` / `（无）`） |
| 4 | 同一次压缩内第二个 `compaction/summary` | `seq N 的 compaction/summary 在一次压缩里重复出现` |
| 5 | `compaction/end` 身份 ≠ openId | 同 #3，`compaction/end` 版文案 |
| 6 | `compaction/end` 不带 error 且本次压缩未见 summary | `seq N 的 compaction/end 没有报错，但这次压缩没有 compaction/summary` |
| 7 | 日志结束仍有未收尾压缩（openId 非空） | `身份 X 的压缩没有 compaction/end 收尾` |
| 8 | `compaction/summary` 缺 shadowedSeqs（缺键 / 非数组 / 元素非整数 / 空数组） | `seq N 的 compaction/summary 缺少 shadowedSeqs` |
| 9 | shadowedSeqs 与「全量事件前 shadowedSeqs.length 条的 seq 序列」不逐一相等 | `seq N 的 compaction/summary 折叠的不是日志开头的一段` |

### 6.2 状态机细则

- `compaction/start`：无论是否违规，openId ← 本条 id（可空），已见 summary ← false；
- `compaction/summary`：检查完后已见 summary ← true（即使身份不匹配也照设）；
- `compaction/end`：检查完后 openId ← nil，已见 summary ← false（即使身份不匹配也照重置）；
- 「失败」判定：data 为对象且 `error` 键存在且值非 null；
- 其他事件类型不参与状态机；
- start 缺 id（openId ← nil）时日志结束不报 #7（nil 视为无进行中压缩）；后续 summary/end 的非空 id 与 nil openId 比较走 #3/#5。

## Swiftus 实现注记

- `Compactor` 为 `@ContextTreeActor final class`（整树单 actor 惯例）；`CompactionSummary` / `CompactionFold` / `CompactionResult` 为 Sendable struct；`Summarizer` 为 `@ContextTreeActor ([SessionEvent], String) async throws -> CompactionSummary`；
- Dart 的 `Expando<_BalanceCache>`（挂在 Session 上的 GC 感知缓存）以 `NSMapTable<AnyObject, AnyObject>`（弱键强值）替代，语义对齐「会话释放则缓存随之回收」；平台 floor（macOS 13 / iOS 16）内可用；
- StateError 级错误对应结构化错误：`ToolPairingError`（结果先于调用 / seq 不在日志）、`CompactionInvariantError`（assert 版）；
- id 生成器（`cmp-` / `evt-`）在 actor 域内维护单调序号；fixtures 比对时 compactionId / time 归一化——校验「三事件同身份」，不比具体值；
- 服务装配沿用 phantom key：`ServiceKey<CompactionEngine>("compaction")`。
